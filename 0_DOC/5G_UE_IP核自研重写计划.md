# 5G UE 物理层 IP 核自研重写计划

> 目标：将 Vivado FFT/IFFT、Polar、LDPC、CORDIC 等 IP 核全部替换为自研 RTL，同时建立 C/MATLAB golden model 用于系统级快速仿真，提升仿真速度并摆脱加密 IP 核黑盒。

---

## 一、总体思路

自底向上、先验证框架后模块、每个模块配 **C/MATLAB golden model + RTL 双轨**。C 模型用于系统级快速仿真，RTL 用于综合和模块级 bit-true 验证。系统级仿真大部分链路跑 C 模型，仅待验证模块跑 RTL，速度比全加密 IP 核行为仿真快一个数量级。

**重写优先级排序原则：** 基础运算单元 → 信号处理（FFT/CORDIC）→ 调制解调 → 信道编解码（Polar 先于 LDPC）→ 速率匹配 → 系统集成。

---

## 二、分阶段计划

### 阶段 0：基础设施（1–2 周）

| 事项 | 要点 |
|---|---|
| 定点化规范 | 统一 Q 格式（如输入 14bit、内部 18bit），定义舍入/截断策略，所有模块共用一份头文件 |
| 验证框架 | Python/MATLAB 生成输入向量和期望输出 → 文件 → RTL testbench 自动读入比对，输出误差统计 |
| 基础运算单元 | 复数乘法器（3 乘法/4 乘法两种结构）、蝶形运算单元、饱和/舍入原语 |
| 仿真加速架构 | 确定 DPI-C 接口规范，C 模型编译成 .so/.dll 供 VCS/ModelSim 直接调用 |

### 阶段 1：CORDIC（1 周）

- **用途**：NCO（载波生成）、频偏补偿、相位旋转、sin/cos、atan、sqrt
- **实现**：流水线式（12–16 级迭代），覆盖旋转模式和向量模式
- **关键**：预补偿增益因子、角度范围扩展、迭代次数与精度折中
- **验证**：与 MATLAB `sin/cos/atan` 对比，量化 ENOB

### 阶段 2：FFT / IFFT（2–3 周）

- **规格**：5G NR 最大 **4096 点**，支持 128/256/512/1024/2048/4096 可配置
- **结构选择**：
  - 资源优先：Radix-2 单蝶形时分复用
  - 吞吐优先：Radix-4 + Radix-2 混合基流水线
  - UE 侧建议：**Radix-2² 流水线**，兼顾面积和吞吐
- **关键**：位反序（bit-reversal）、旋转因子用 CORDIC 生成省 LUT、块浮点/定点溢出控制
- **验证**：与 MATLAB `fft()` 逐点比对，测 SNR 和 EVM

### 阶段 3：调制 / 软解调（1 周）

- **调制**：QPSK / 16QAM / 64QAM / 256QAM，查表或公式法
- **软解调**：LLR 计算（Max-Log-MAP 近似），接收链路关键路径
- **验证**：LLR 分布与 MATLAB 对比，误码率曲线对齐

### 阶段 4：Polar 编解码（3–4 周）

**编码（简单，0.5 周）：**
- 5G NR Polar：N ∈ {32, 64, ..., 1024}，K ≤ 512
- 比特反转 + F 矩阵递归，RTL 直接组合逻辑或少量时序

**译码（难点，2.5–3 周）：**
- 算法：**CA-SCL（CRC-Aided SCL）**，L=8 或 L=16
- 5G 特定：32bit CRC 辅助、PC（Parity Check）比特、子块交织
- 实现要点：
  - L 个候选路径的度量存储与排序（用部分排序网络，别全排序）
  - 内部 LLR 位宽（通常 6–8bit 足够）
  - 递归结构展开成流水线或时分复用
- **验证**：与 MATLAB Polar 译码器对比 BLER 曲线，重点测低 SNR 区域

### 阶段 5：LDPC 编解码（4–5 周）

**编码（1 周）：**
- 准循环 LDPC（QC-LDPC），BG1/BG2 两种基矩阵
- Zc ∈ {2, 3, 4, ..., 384}，共 51 个值
- 编码本质是稀疏矩阵乘 + 循环移位，用移位寄存器组实现

**译码（难点，3–4 周）：**
- 算法：**Layered Min-Sum（分层最小和）**，归一化因子 0.75–0.875
- 实现要点：
  - 校验节点更新（找最小/次小 + 符号处理）
  - 变量节点更新
  - 存储：LLR RAM（按 Zc 分组）、校验消息 RAM
  - 迭代次数可配（通常 4–8 次）
  - 提前终止（校验通过即停）
- **验证**：与 MATLAB `ldpcDecode` 或 5G Toolbox 对比 BLER，测不同码率和 Zc

### 阶段 6：速率匹配 / 解速率匹配（2 周）

- **Polar 侧**：子块交织（32 行矩阵）、比特选择（环形缓冲）、发送端交织
- **LDPC 侧**：比特选择（列删/重复）、交织（BG2 用）、虚拟比特填充
- 逻辑不复杂但**极其繁琐**，建议直接对照 38.212 表格写，逐个子 case 验证

### 阶段 7：系统集成与仿真优化（2–3 周）

- 端到端链路：PDSCH 发射 → 信道 → 接收全链路跑通
- 仿真加速：系统级仿真全部用 C 模型（DPI-C），仅在模块验证时切 RTL
- 性能对比：自研 vs Vivado IP 的仿真速度、资源占用、时序、误码率

## 三、关键风险与应对

| 风险 | 应对 |
|---|---|
| LDPC/SCL 译码器复杂度失控 | 先做 C 模型确定算法和位宽，再写 RTL；不要一上来就写 RTL |
| 定点化精度不够导致 BLER 损失 | 每个模块单独做定点仿真，确定最小位宽，留 1–2bit 余量 |
| 5G 规范细节多（38.212/38.211） | 用 5G Toolbox 或 srsRAN 作为 golden reference，不要自己猜规范 |
| 仿真加速效果不达预期 | C 模型用 float 快速仿真，RTL 只在模块级验证；系统级别混跑 |
| FFT 旋转因子 LUT 太大 | 用 CORDIC 实时生成旋转因子，或只存 1/4 周期利用对称性 |

---

## 四、推荐 Golden Reference

- **MATLAB 5G Toolbox**：`nrPolarEncode` / `nrLDPCEncode` / `nrOFDMModulate` 等，最权威
- **srsRAN（C++ 开源）**：可直接拿来当 C 模型，与 RTL 比对
- **自写 C 模型**：按 38.212 逐行实现，同时作为仿真加速模型

## 六、起步建议

**先做阶段 0 + 阶段 2（FFT）**：FFT 是替换需求中最核心、收益最明显的模块，且做完 FFT 后验证框架也跑通了，后续模块会顺很多。Polar 和 LDPC 译码器是硬骨头，建议放在验证框架充分建立之后再动。
